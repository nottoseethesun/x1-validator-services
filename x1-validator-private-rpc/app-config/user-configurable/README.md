# Your Settings

Put your own settings for x1-validator-private-rpc in this folder, in `private-rpc.json`. The file holds only the settings you change. The tool merges it over the shipped defaults, setting by setting. The defaults are in `../app-defaults-for-user-configurable/private-rpc.json`, and what each setting does is in the schema beside it, `private-rpc.schema.json`. Every command checks the merged settings first, and stops with every problem named, so a typo can't be ignored.

The tool's `apply` command sets everything up, as the feature's [README](../../README.md) describes. It needs one setting that has no default: `hostname`, the name your clients will use for the rpc. The README's [Set the Hostname](../../README.md#set-the-hostname) step starts this file as a copy of `../app-defaults-for-user-configurable/private-rpc.example.json`. The README's [Configure](../../README.md#configure) section says which changes need `apply` again, and in what order to change `hashedApiKeysPath` or `hashedApiKeysMapPath`.

`git` ignores every file here but this README, so an update's `git pull` leaves your settings alone. The tool reads only `private-rpc.json`, so settings saved under another name, such as `private_rpc.json`, would be ignored without a word. So the tool refuses to run while the folder holds another file whose name ends in `.json` and doesn't start with a dot. Every other file passes. That covers a name that doesn't end in `.json`, such as `private-rpc.json.save`, which `nano` can leave behind. It also covers a name that starts with a dot, such as `.#private-rpc.json`, the lock file Emacs keeps while an edit is unsaved.
